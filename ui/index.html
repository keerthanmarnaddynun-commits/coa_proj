Pollution-Aware Markov Page Prefetching

COA Project
🎤 Presenter Notes (Tab 1: Overview) Click to collapse
  • The Core Bottleneck: In virtual memory systems, a page fault triggers disk/SSD I/O requiring millions of CPU cycles (~8 ms) versus ~100 ns for a RAM access (an 80,000x latency penalty).
  • Why Graph Traversal is Hard: Parallel BFS over sparse graphs (e.g. Amazon0302 co-purchasing graph) exhibits irregular, data-dependent memory access patterns that defeat standard hardware stride prefetchers.
  • The Danger of Speculation (Cache Pollution): While 1st-order Markov prefetching can mask miss latency, speculative wrong guesses evict active working set pages, raising page faults when free memory is limited.
  • Architectural Remedies: We demonstrate three orthogonal pollution remedies: confidence thresholding (T=0.10), LRU-end insertion (prefetch-aware LRU), and closed-loop adaptive degree control.

The Challenge: Virtual Memory Latency vs Cache Pollution

In Computer Organization & Architecture, demand paging waits until a memory miss halts CPU execution. Prefetching fetches speculative pages early to hide latency, but inaccurate predictions cause cache pollution—flushing active working set frames.

🎤 Presenter Notes (Tab 5: Conclusions) Click to collapse
  • Summary for Evaluation Panel: 1st-order Markov prefetching achieves a 15.04% fault reduction on irregular graph BFS workloads, but naive prefetching causes severe cache pollution under constrained memory (-7.26%).
  • The Three Solutions: We developed confidence thresholding (+17.65%), LRU-end insertion (+13.54%), and adaptive feedback control (+4.29% at 512 frames); LRU-end insertion and adaptive control both turn the 512-frame loss into a gain.
  • Transparent Scientific Integrity: We documented negative results (2nd-order, per-thread, ARC) and stated clear project limitations (single BFS workload, fully associative software cache model, offline threshold tuning).
5 Core Project Takeaways Conclusions
  • Top-3 is the Best Degree Tested: At 1,024 frames, degree k=3 cuts page faults by 15.04% (67,696 → 57,512). Top-5 saves less (+6.88%); one possible cause is that extra low-probability pages displace resident ones, which we did not test.
  • Ungated Prefetching Can Raise Faults: At 512 frames, ungated Top-3 with MRU insertion increases faults by 7.26% (221,603 → 237,684). In this run, prefetching without pollution control made things worse.
  • Three Orthogonal Solutions Address Pollution:
    • Confidence Filter (T=0.10): Prunes low-probability transitions, yielding peak +17.65% reduction with 7,382 fewer prefetches.
    • LRU-End Insertion: Places speculative pages at the LRU position, turning a -7.26% loss at 512 frames into a +13.54% gain.
    • Adaptive Top-K Controller: Dynamically throttles k when waste exceeds 50%, rescuing constrained memory autonomously (+4.29% gain).
  • Negative Results: 2nd-order Markov did worse than baseline at k=2, 3 and 5 (403,006 states); per-thread models did worse than the global model; ARC gave no benefit over LRU. The causes were not tested.
  • Markov Table Close to the Graph Oracle: Top-3 Markov gives 57,512 faults against 57,230 for the graph oracle, which is 97.3% of the oracle's saving (10,184 of 10,466 faults). The oracle is built from the whole graph with page numbers copied from this trace's layout, so it is not independent.
Experimental Limitations Scientific Rigor
  • Single Workload & Graph Topology: Evaluated exclusively on parallel BFS over the SNAP Amazon0302 co-purchasing graph (262,111 vertices, 1,234,877 edges). Behavior on power-law social networks or DFS traversals may differ.
  • Fully Associative Software Simulator: Implemented a fully associative software LRU cache. Real hardware L1/L2/L3 caches and TLB structures are set-associative with collision conflict misses.
  • Uncharged Background I/O Overhead: Demand faults stall CPU execution, but prefetch I/O bandwidth and memory bus saturation are not charged as latency penalties in the simulator.
  • Threshold Tuning on Test Trace: Confidence threshold T=0.10 was evaluated on the test trace; dynamic online confidence estimation was not integrated.
  • Fixes Evaluated Separately: The three pollution fixes (thresholding, LRU-end insertion, adaptive control) were evaluated independently rather than in an integrated compound architecture.
  • Two Distinct Trace Datasets: Trace A (Experiments 1–8) and Trace B (Experiments 9–11) are two separate runs of the same parallel BFS and differ by about 1% because of OpenMP scheduling: baseline LRU at 1,024 frames has 67,696 faults on Trace A and 66,979 on Trace B. Trace B also records thread numbers and write flags, which E9-E11 need.
